# v0.2.0 Architecture Decisions

**Date**: 2026-07-24  
**Status**: Approved  

---

## ADR-001: Single Repository Structure

**Decision**: Keep `cogalpha-research-mvp` as the single repository. Add `apps/` directory for product layers.

**Rationale**: Avoids multi-repo complexity for a single-user local product. Simplifies CI, versioning, and releases.

## ADR-002: FastAPI for Backend

**Decision**: Use FastAPI + Pydantic v2 for the API layer.

**Rationale**: FastAPI is async-native, has automatic OpenAPI docs, type-safe with Pydantic, and widely adopted. No commercial license needed.

## ADR-003: React + TypeScript + Vite for Frontend

**Decision**: Use React 18 + TypeScript + Vite for the web interface.

**Rationale**: Industry standard, large ecosystem, Vite provides fast dev builds. TypeScript ensures type safety.

## ADR-004: SQLite for Metadata

**Decision**: Use SQLite (via SQLAlchemy 2.x) for all metadata storage. Never store market data in the database.

**Rationale**: Zero-configuration, single-file, sufficient for single-user local product. Avoids Redis/PostgreSQL dependency.

## ADR-005: Background Job Manager (No Celery/Redis)

**Decision**: Implement a custom persistent job manager using SQLite + threading.

**Rationale**: v0.2.0 is single-user local. Celery/Redis adds unnecessary complexity. SQLite-based job state enables crash recovery.

## ADR-006: Apache ECharts for Visualization

**Decision**: Use Apache ECharts (via echarts-for-react) for all charts.

**Rationale**: Apache 2.0 licensed, excellent financial chart support, large community. No commercial license needed.

## ADR-007: Localhost-Only Default Binding

**Decision**: Default API binding to 127.0.0.1:8765. No 0.0.0.0.

**Rationale**: Security-first. Local product should not expose ports to network by default.

## ADR-008: Preserve cogalpha_mvp Package Name

**Decision**: Keep `cogalpha_mvp` as the Python package name. Product name is "CogAlpha Studio".

**Rationale**: Avoids breaking changes to existing CLI, imports, and tests. Reduces migration risk.

## ADR-009: DuckDB for Large Data Queries

**Decision**: Use DuckDB for analytical queries on Parquet files.

**Rationale**: Columnar, embedded, no server needed. Efficient for financial data aggregation without loading full datasets into memory.

## ADR-010: Phase-Based Delivery

**Decision**: Deliver in 5 phases: (1) Architecture & Persistence, (2) API & Jobs, (3) Frontend, (4) Install & Docker, (5) Tests & Docs.

**Rationale**: Each phase is independently testable. Allows incremental CI verification.
